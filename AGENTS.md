# Rules for coding agents working in this repository

## What this lab is

Two agents are given identical questions, identical functions, identical mock
data, an identical system prompt, and the same model. The only thing that
differs is how the tools are described to the model. The site lets a visitor
run that comparison live and watch the two executions diverge.

The single claim this lab makes is that the **declaration** decides the
outcome, and that within the declaration the prose carries far more weight
than the tool name. Everything in the repository exists to support or
qualify that claim. Do not add features that dilute it.

## Rules

1. **Accuracy over polish.** Every number quoted on the site must be
   reproducible from `data/traces/*.json`. If a claim cannot be traced to a
   recorded run, it does not go on the page.

2. **Never claim a result the visitor cannot see.** Runs are live and
   probabilistic. The summary line under the comparison is generated from the
   two transcripts just produced by `diagnose()` in `components/LiveDemo.tsx`.
   Do not replace it with fixed copy.

3. **Publish every run.** All 36 recorded runs are committed. Never select a
   favourable subset, and never quietly drop a scenario that failed to
   reproduce. `RETIRED_SCENARIOS` in `agent/record.py` exists because five
   scenarios did not differentiate, and that null result is what redirected
   the lab towards arguments.

4. **A tool is not a Python function.** A tool wraps an API call, a database
   query, an MCP operation, or a workflow step. In this lab they happen to be
   Python. Never write copy that generalises the sample into a definition.

5. **The model reads the whole declaration.** Name, description, and parameter
   schema. Never write that it sees only the description. The Wall component
   displays the schema, so that claim contradicts the page it sits on.

6. **Parity between the Python and the TypeScript.** `lib/live/schemas.ts` is
   generated by `agent/export_schemas.py` and must never be hand edited.
   `data/wall.json` is generated by `agent/export_wall.py`. `lib/live/tools.ts`
   is a hand port of `agent/tools.py` and is the one place drift is possible;
   change both sides together and re-run `python agent/record.py`.

7. **Voice.** No em dashes anywhere, including code comments. No contractions
   in body text. British spelling. Short declaratives against longer
   explanatory sentences. Lists written as sentences separated by full stops
   rather than bullets. Match the Perspectives articles on eleganceai.ai.

8. **Keep the demo page simple.** One question, one button, two panels, three
   short explainer blocks. The depth belongs in `/guide` and in the
   repository. An earlier version presented the full experiment on the demo
   page and was rejected as too much.

9. **Never expose secrets.** `ANTHROPIC_API_KEY` stays server side. Never
   prefix it with `NEXT_PUBLIC_`. Never log it. Never commit `.env`.

10. **Cost and abuse.** The live endpoint spends real money at roughly four
    cents per press. Keep the rate limit, the length cap, and the relevance
    gate in `app/api/lab/good-tools-bad-tools/run/route.ts`. Note that the
    rate limit is in memory and therefore per instance.

11. Run `npm run build` before declaring work done. Verify pages return 200
    and check for horizontal overflow at 320px and 390px.

12. Summarise changed files at the end of a session.

13. Do not push or deploy unless explicitly instructed.
